# C005 mark-class-conflict

**Severity:** error · **Fix:** none

## What it reports

Two mark classes that share a glyph, attached by rules in the same lookup
(`pos base`, `pos ligature` or `pos mark` rules).

## Why it matters

A mark-attachment lookup gives each mark one class, so fea-rs and fontTools
both reject the file. fea-rs's message doesn't name the glyph; this one does,
and it shows while you edit rather than when the font is built.

## Example

```fea
markClass acutecomb <anchor 0 500> @TOP;
markClass acutecomb <anchor 0 -10> @BOTTOM;
feature mark {
    pos base a <anchor 250 500> mark @TOP;
    pos base a <anchor 250 0> mark @BOTTOM;   # C005: acutecomb is in both
} mark;
```

## Notes

The same glyph may be in two mark classes used in different lookups. Put the
rules for each class in their own `lookup` block.
