# R001 unreachable-rule

**Severity:** warning · **Fix:** none

## What it reports

A contextual rule (`sub` or `pos` with marked glyphs, or `ignore`) that never
runs, because an earlier rule in the same lookup matches every sequence it
matches.

## Why it matters

Within a lookup, the first rule that matches at a position wins and the rest
aren't tried. Compilers accept the later rule without a word, and it silently
does nothing. Usually the more specific rule was meant to come first.

## Example

```fea
feature calt {
    sub a' by a.alt;
    sub a' c by a.short;   # R001: the rule above already matches every a
} calt;
```

Swap them, so the specific rule is tried first:

```fea
feature calt {
    sub a' c by a.short;
    sub a' by a.alt;
} calt;
```

## Notes

A later rule that forms a longer ligature with `by` (`sub x a' b' c' by abc;`
after `sub x a' b' by ab;`) isn't reported: both compilers put a lookup's
inline ligatures into one ligature lookup that forms the longest match, so the
longer ligature still forms (checked with HarfBuzz).

When the earlier rule does the same thing as the later one (both `ignore`, or
the same lookups at the same positions), nothing is lost: that's reported as
[R006](R006.md) instead. An earlier rule matches everything a later one does when each of its glyph
positions (backtrack, marked glyphs and lookahead, counted from the first
marked glyph) holds every glyph the later rule has there, and it has no
positions the later one lacks. Rules with Glyphs predicates or classes that
can't be expanded are skipped. A `lookupflag`, `script`, `language` or `lookup`
statement starts a new lookup, and the comparison starts over.
