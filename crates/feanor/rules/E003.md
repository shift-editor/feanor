# E003 languagesystem-after-feature

**Severity:** warning · **Fix:** unsafe (move it above the first feature)

## What it reports

A top-level `languagesystem` statement that comes after a `feature` block.

## Why it matters

The OpenType feature file specification requires every `languagesystem`
statement before the first feature. fea-rs and fontTools accept a late one,
but it then applies only to the features after it: features above it aren't
registered for that script and language.

Once anything registers that script in the same table, shapers use only what's
registered there. Checked with HarfBuzz: in the example, `fi` stops forming a
ligature in text marked as Latin, while it still forms in text with no script.

## Example

```fea
languagesystem DFLT dflt;
feature liga { sub f i by f_i; } liga;
languagesystem latn dflt;   # E003: liga isn't registered for latn
feature salt { sub a by a.alt; } salt;
```

## Fix

Moves the statement after the last `languagesystem` above the first feature.
**Unsafe:** the features above it start applying to that script and language.
