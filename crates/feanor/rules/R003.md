# R003 duplicate-pair

**Severity:** warning · **Fix:** safe (remove the ignored rule)

## What it reports

The same pair of glyphs positioned twice in one lookup, as glyph pairs
(`pos A V -80;`) or through `enum pos`.

## Why it matters

fea-rs and fontTools both keep the first value and silently ignore the later
one, so a correction added further down a kerning list has no effect.

## Example

```fea
feature kern {
    pos T o -60;
    pos T o -45;   # R003: ignored; -60 wins
} kern;
```

## Fix

When every pair in the later rule is already positioned, removes that rule.
**Safe:** the rule is ignored, so the compiled font doesn't change. If the
later value is the one you want, change the earlier rule instead.

## Notes

The same pair repeated with the same value changes nothing and is reported as
[R006](R006.md) instead. Class pairs (`pos @A @B`, or `pos [a e] v` without `enum`) aren't checked:
they compile to their own subtables, where specific glyph pairs take
precedence by design.
