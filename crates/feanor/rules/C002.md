# C002 duplicate-glyph-in-class

**Severity:** warning · **Fix:** safe (remove the repeat)

## What it reports

The same glyph twice in one glyph class.

## Why it matters

makeotf warns about it and fontTools feaLib rejects some cases, so the same
file can behave differently across compilers. A repeat is usually a copy-paste
slip.

## Example

```fea
@marks = [acutecomb gravecomb acutecomb];   # C002: 'acutecomb' is already in this class
```

## Fix

Removes the second occurrence. **Safe:** a glyph class is a set for matching
purposes.

## Notes

Classes whose order matters are never reported. In a substitution from one
class to another (`sub @A by @B;`, `sub [a b c] by [x y z];`, the contextual
`sub c @A' by @B;`, or a reverse substitution), glyphs are paired by index, so a repeat on either side can be
meaningful and removing it would shift every pair after it. Repeats after `by`
are always kept: in `sub [Alphatonos Alpha] by [Alpha Alpha];` each target needs
its own replacement. A class defined with `@name = [...]` and used in any of
these places is exempt everywhere.
